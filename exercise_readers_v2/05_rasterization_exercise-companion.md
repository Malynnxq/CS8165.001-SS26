# Task 1 — Primitive, fragment, and pixel

Explain the difference between:

1. a triangle;
2. a fragment;
3. a framebuffer pixel/sample value.

Why is it incorrect to say that rasterization simply “turns triangles into pixels”?

## Lecture connection

Lecture 6 §1 and §16.

## Solution

A **triangle** is a continuous geometric primitive. Mathematically it covers infinitely many points.

A **fragment** is a candidate contribution generated by rasterization for a covered discrete sample location. It can carry interpolated depth, color, texture coordinates, normals, etc.

A **framebuffer value** is what remains stored after later fragment operations such as depth testing and blending.

Therefore:

```text
triangle
↓ rasterization
fragments
↓ fragment/depth/blending operations
stored framebuffer values
```

Rasterization does not guarantee that every generated fragment becomes a final visible pixel.

# Task 2 — Which axis should a line rasterizer step along?

For each line slope, decide whether a simple rasterizer should primarily advance one integer step in `x` or in `y`:

A. `m = 0.25`

B. `m = 0.9`

C. `m = 2`

D. `m = -4`

Explain why.

## Lecture connection

Lecture 6 §2.

## Solution

For shallow lines, `|m| ≤ 1`, advance primarily in `x` so roughly one sample is chosen per column.

For steep lines, `|m| > 1`, advance primarily in `y` so roughly one sample is chosen per row.

Therefore:

- A: x
- B: x
- C: y
- D: y

If a steep line were advanced only one column at a time, it could jump several rows between consecutive selected samples and leave gaps.

# Task 3 — Naïve line rasterization

Consider the segment from

\[
(0,1)
\]

to

\[
(4,3).
\]

1. Calculate its slope.
2. Write the explicit line equation `y = mx + B`.
3. Evaluate `y` for integer `x = 0,1,2,3,4`.
4. Round each value to obtain a simple raster approximation.

## Lecture connection

Lecture 6 §3.

## Solution

The slope is

\[
m=\frac{3-1}{4-0}=\frac12.
\]

Since `y(0)=1`,

\[
B=1.
\]

Thus

\[
y=0.5x+1.
\]

Values:

| x | ideal y | rounded y |
|---:|---:|---:|
| 0 | 1.0 | 1 |
| 1 | 1.5 | depends on tie convention, commonly 2 |
| 2 | 2.0 | 2 |
| 3 | 2.5 | commonly 3 |
| 4 | 3.0 | 3 |

One possible sample sequence is

```text
(0,1), (1,2), (2,2), (3,3), (4,3)
```

### Why this is not the final algorithm

Repeatedly evaluating `mx+B` uses floating-point arithmetic and rounding. Vertical lines also make the slope representation problematic, and steep lines need a different stepping direction.

# Task 4 — DDA

Use the same line from `(0,1)` to `(4,3)`.

Show how DDA avoids recomputing the line equation.

## Lecture connection

Lecture 6 §4.

## Solution

The slope is

\[
m=0.5.
\]

Start with

\[
y=1.
\]

Each time x increases by one,

\[
y_{new}=y_{old}+0.5.
\]

So:

```text
x=0: y=1.0
x=1: y=1.5
x=2: y=2.0
x=3: y=2.5
x=4: y=3.0
```

DDA performs the slope calculation once and then repeatedly adds `m`.

The improvement is not a different geometric line. It is a cheaper way of obtaining the same sequence of ideal y-values.

### General principle

This is **spatial coherence**:

> The next sample is close to the current one, so update from what you already know.

# Task 5 — Midpoint candidate pixels

Assume a line has

\[
0\le m\le1.
\]

The current rasterized pixel is

\[
P=(x_p,y_p).
\]

1. What are the only two candidate pixels for the next column?
2. What midpoint is tested between them?
3. What geometric question does the midpoint test answer?

## Lecture connection

Lecture 6 §5.

## Solution

The candidates are

\[
E=(x_p+1,y_p)
\]

and

\[
NE=(x_p+1,y_p+1).
\]

Their midpoint is

\[
M=(x_p+1,y_p+\tfrac12).
\]

The algorithm asks whether the ideal mathematical line passes above or below that midpoint.

That tells us whether `E` or `NE` is the closer discrete approximation.

The clever part is that we do **not** need the exact distance to either pixel. We need only a binary side-of-line decision.

# Task 6 — Why use an implicit line equation?

Compare these two line representations:

\[
y=mx+B
\]

and

\[
F(x,y)=ax+by+c=0.
\]

Why is the second form especially useful for midpoint rasterization?

## Lecture connection

Lecture 6 §6.

## Solution

The explicit equation answers:

> “What y-value does the line have at this x?”

The implicit equation answers a different question through its sign:

```text
F(x,y) > 0  → one side of line
F(x,y) = 0  → on line
F(x,y) < 0  → other side
```

The midpoint algorithm needs exactly this side classification.

So define a decision variable

\[
d=F(M).
\]

Then only the sign of `d` matters.

This converts a geometric closeness problem into a cheap comparison.

# Task 7 — Midpoint/Bresenham-style calculation

Rasterize the line from

\[
(5,8)
\]

to

\[
(9,11)
\]

for the `0 ≤ m ≤ 1` case using

\[
dx=x_1-x_0,
\qquad
dy=y_1-y_0,
\]

\[
d_0=2dy-dx.
\]

Use these updates:

- if E is selected: `d ← d + 2dy`;
- if NE is selected: `d ← d + 2dy - 2dx`.

Use the convention `d ≥ 0 → NE`, `d < 0 → E`.

## Lecture connection

Lecture 6 §7–8.

## Solution

First,

\[
dx=9-5=4,
\]

\[
dy=11-8=3.
\]

Initial decision variable:

\[
d=2(3)-4=2.
\]

Start at `(5,8)`.

### Step 1

`d=2 ≥ 0`, choose NE:

\[
(6,9).
\]

Update:

\[
d=2+6-8=0.
\]

### Step 2

`d=0`, tie convention chooses NE here:

\[
(7,10).
\]

Update:

\[
d=0+6-8=-2.
\]

### Step 3

`d=-2 < 0`, choose E:

\[
(8,10).
\]

Update:

\[
d=-2+6=4.
\]

### Step 4

`d=4 ≥ 0`, choose NE:

\[
(9,11).
\]

One valid sequence under this explicitly stated convention is therefore

```text
(5,8)
(6,9)
(7,10)
(8,10)
(9,11)
```

### Important note

Exact tie-handling conventions can alter which equally plausible boundary sample is selected. The exam-level idea is to understand the recurrence and apply the convention given in the question consistently.

# Task 8 — Why incremental decision updates work

Why can the midpoint decision variable be updated with fixed increments instead of reevaluating the full line equation at every step?

## Lecture connection

Lecture 6 §7.

## Solution

The implicit line equation is linear:

\[
F(x,y)=ax+by+c.
\]

Moving by a fixed grid displacement changes `F` by a fixed amount.

For example,

\[
F(x+1,y)-F(x,y)=a.
\]

Likewise, moving one unit in both x and y changes it by

\[
a+b.
\]

Since the rasterizer repeatedly makes only a small number of fixed moves, their effects can be precomputed.

Thus the inner loop becomes mostly:

```text
compare
add
increment coordinates
```

instead of divisions, multiplications, floating-point evaluations and rounding.

# Task 9 — Reversibility

Why might drawing a line from A to B produce a different sample set than drawing from B to A if tie cases are handled carelessly?

Why does that matter for triangle meshes?

## Lecture connection

Lecture 6 §9–10.

## Solution

When the ideal line passes exactly halfway between two candidate samples, either candidate may be geometrically equally close.

If one traversal direction chooses one sample while the reverse traversal chooses the other, the rasterization is not reversible.

For isolated lines this may be a minor visual difference. For shared polygon edges it can cause:

- cracks if neither neighboring primitive owns a sample;
- double processing if both own it.

Therefore rasterizers need deterministic tie/edge ownership rules.

# Task 10 — The top-left rule

Two triangles share an edge and together form a rectangle.

Why should samples exactly on their shared edge not simply be included by both triangles?

What is the purpose of a top-left-style rule?

## Lecture connection

Lecture 6 §10.

## Solution

If both triangles include every shared-edge sample, those locations are generated twice. This can matter with blending, stencil operations, or other fragment processing.

If both exclude them, cracks can appear.

A deterministic ownership convention such as the top-left rule makes one triangle include the boundary while the adjacent triangle excludes the same boundary.

The goal is:

\[
\text{each shared boundary sample belongs to exactly one primitive.}
\]

The exact “top/left” orientation convention is less important conceptually than consistent unique ownership.

# Task 11 — 4-connectivity versus 8-connectivity

Consider this tiny raster:

```text
X .
. X
```

Are the two `X` pixels connected under:

1. 4-connectivity?
2. 8-connectivity?

Explain.

## Lecture connection

Lecture 6 §12.

## Solution

Under **4-connectivity**, neighbors must share an edge: left, right, up, or down. The two X pixels touch only at a corner, so they are **not connected**.

Under **8-connectivity**, diagonal neighbors count, so they **are connected**.

Therefore every 4-connected path is also 8-connected, but not every 8-connected region is 4-connected.

# Task 12 — Flood fill versus boundary fill

For each situation, choose flood fill or boundary fill.

A. Replace all connected white pixels around a seed with blue.

B. Fill the inside of a region until a red outline is encountered, regardless of the exact interior colors.

## Lecture connection

Lecture 6 §13.

## Solution

A → **flood fill**.

The region is identified by a target old color.

B → **boundary fill**.

The stopping condition is the boundary color rather than equality with one interior color.

### Implementation warning

Naïve recursive implementations can recurse once for huge numbers of pixels and overflow the call stack. An explicit stack or queue is safer for large regions.

# Task 13 — Why triangle scanline filling works

Why does a horizontal scanline normally intersect the interior of a triangle in at most one continuous interval?

How does this property simplify rasterization?

## Lecture connection

Lecture 6 §15.

## Solution

A triangle is **convex**.

For a convex set, the intersection with a line is empty, a point, or one continuous segment. It cannot leave the triangle and then re-enter it multiple times.

Therefore a rasterizer can determine:

```text
left intersection
right intersection
```

and generate fragments between them.

This is much simpler than filling an arbitrary concave polygon, where one scanline may contain multiple disjoint interior intervals.

# Task 14 — Split a triangle for scan conversion

A triangle has vertices

```text
A = (2,1)
B = (7,4)
C = (4,9)
```

After sorting by y, identify:

1. lowest vertex;
2. middle vertex;
3. highest vertex;
4. the long edge active across the whole vertical range;
5. which shorter edge is active before and after the middle y-coordinate.

## Lecture connection

Lecture 6 §15.

## Solution

The y-values are

```text
A: 1
B: 4
C: 9
```

so the order is

\[
A\rightarrow B\rightarrow C.
\]

The long edge is

\[
A\rightarrow C.
\]

For the lower half, the other active edge is

\[
A\rightarrow B.
\]

For the upper half, it changes to

\[
B\rightarrow C.
\]

So:

```text
y=1 ... 4 : edges AC and AB

```

This decomposition lets each half be rasterized using two y-monotonic edges.

# Task 15 — Incremental edge walking

An edge goes from

\[
(2,2)
\]

to

\[
(8,6).
\]

Calculate

\[
\frac{dx}{dy}
\]

and explain how it can be used to update the x-coordinate of the edge intersection from one scanline to the next.

## Lecture connection

Lecture 6 §11 and §15.

## Solution

\[
dx=8-2=6,
\]

\[
dy=6-2=4.
\]

Thus

\[
\frac{dx}{dy}=\frac64=1.5.
\]

If the edge intersects one scanline at `x`, then the next scanline's ideal intersection is

\[
x_{new}=x+1.5.
\]

Again, this avoids solving the entire edge equation independently on every scanline.

It is the same coherence principle as DDA, now applied to triangle boundaries.

# Task 16 — Attribute interpolation

A horizontal scanline crosses a triangle from

```text
left endpoint color  = (1,0,0)
right endpoint color = (0,0,1)
```

Suppose a fragment lies exactly halfway between those endpoints.

Using linear interpolation, what color does it receive?

## Lecture connection

Lecture 6 §17–18.

## Solution

Linear interpolation is

\[
C(t)=(1-t)C_L+tC_R.
\]

At the midpoint,

\[
t=0.5.
\]

Therefore

\[
C=0.5(1,0,0)+0.5(0,0,1)
=(0.5,0,0.5).
\]

So the fragment receives equal red and blue contributions.

### Pipeline meaning

Vertex attributes exist only at vertices initially. Rasterization produces per-fragment values by interpolation so the fragment shader has meaningful inputs.

# Task 17 — Incremental depth interpolation

Suppose depth along one scanline varies linearly from

\[
z=0.2
\]

at x=10 to

\[
z=0.7
\]

at x=15.

Assume five unit x-steps separate the endpoints.

1. Calculate `dz/dx`.
2. List the depth values at x=10 through x=15.

## Lecture connection

Lecture 6 §18; forward connection to Lecture 7 depth testing.

## Solution

The total change is

\[
0.7-0.2=0.5.
\]

Over five x-steps,

\[
\frac{dz}{dx}=\frac{0.5}{5}=0.1.
\]

So:

```text
x=10 → 0.2
x=11 → 0.3
x=12 → 0.4
x=13 → 0.5
x=14 → 0.6
x=15 → 0.7
```

Instead of recalculating depth from the triangle plane at every fragment, the rasterizer can repeatedly execute

```text
z += 0.1
```

for this scanline.

# Task 18 — Edge functions

A directed 2D edge from

\[
A=(x_0,y_0)
\]

to

\[
B=(x_1,y_1)
\]

can be represented by an edge function of the form

\[
E(x,y)=(y_0-y_1)x+(x_1-x_0)y+x_0y_1-x_1y_0.
\]

For the edge from `(0,0)` to `(4,0)`, simplify `E(x,y)` and determine its sign for the points `(2,2)` and `(2,-2)`.

## Lecture connection

Lecture 6 §20.

## Solution

Insert

```text
x0=0, y0=0
x1=4, y1=0
```

Then

\[
E(x,y)=(0-0)x+(4-0)y+0-0=4y.
\]

At `(2,2)`:

\[
E=8>0.
\]

At `(2,-2)`:

\[
E=-8<0.

# Task 20 — Scanline versus tile-based rasterization

Compare scanline and tile-based triangle rasterization in terms of:

1. spatial coherence;
2. sequential dependencies;
3. GPU parallelism.

## Lecture connection

Lecture 6 §19–24.

## Solution

### Scanline rasterization

It exploits coherence very strongly. Edge positions and attributes can be updated from one sample/scanline to the next.

But this naturally creates sequential dependencies:

```text
current state → next state → next state → ...
```

That makes massive independent parallel execution less natural.

### Tile-based rasterization

The screen is divided into blocks. Candidate tiles/samples can be tested independently with edge functions.

Some cross-tile incremental reuse is lost or must be reinitialized, but the independence maps much better to modern parallel GPU hardware.

The tradeoff is therefore roughly:

```text
scanline: maximize sequential reuse
vs.
tiles: maximize independent parallel work
```

# Task 21 — Bounding-box rejection

A screen-space triangle has vertices

```text
(10,20), (50,30), (25,80)
```

Find its axis-aligned bounding box.

Why is this useful before evaluating edge functions for every screen sample?

## Lecture connection

Lecture 6 §21.

## Solution

Minimum and maximum coordinates:

\[
x_{min}=10,
\qquad x_{max}=50,
\]

\[
y_{min}=20,
\qquad y_{max}=80.
\]

So the bounding box is

```text
x ∈ [10,50]
y ∈ [20,80]
```

Any sample outside this rectangle certainly cannot lie inside the triangle.

Therefore the rasterizer can first restrict work to candidate tiles/samples overlapping this box, then perform the more precise three-edge coverage tests only there.

# Task 22 — Full conceptual rasterization problem

A triangle has already survived clipping and has been transformed into screen coordinates.

Explain the complete sequence a tile/edge-function rasterizer conceptually follows until a fragment reaches the depth test.

## Lecture connection

Lecture 5 → Lecture 6 → Lecture 7.

## Solution

A simplified chain is:

```text
screen-space triangle
↓
find candidate bounding box / tiles
↓
for candidate sample locations:
    evaluate three edge functions
↓
apply boundary ownership convention
↓
covered sample?
    no  → discard candidate
    yes → generate fragment
↓
interpolate depth and other vertex attributes
↓
fragment processing
↓
depth test / visibility determination [Lecture 7]
↓
possibly update framebuffer
```

The key distinction is that rasterization determines **coverage and interpolated fragment data**. It does not by itself decide final visibility.

# Task 23 — Diagnose a crack between triangles

Two triangles form a continuous surface but a thin one-pixel crack occasionally appears along their shared edge.

Give two rasterization-related conceptual causes you would investigate.

## Lecture connection

Lecture 6 §9–10.

## Solution

First, investigate **inconsistent shared-edge ownership/tie handling**. If each triangle excludes a boundary sample under slightly different rules, neither generates it.

Second, investigate **numerical inconsistency** in evaluating the same geometric edge from opposite directions or with different arithmetic paths. If one triangle classifies a sample as outside while the other also classifies it as outside, a crack results.

A deterministic top-left-style convention and consistent edge evaluation are designed precisely to avoid these problems.

# Task 24 — Why rasterization loves linear functions

The lecture repeatedly uses incremental updates for:

- line decisions;
- triangle edge positions;
- depth;
- colors/attributes;
- edge functions.

Explain the mathematical reason this is possible.

## Lecture connection

Lecture 6 §23.

## Solution

Many quantities involved are linear or affine functions of screen coordinates.

For

\[
f(x,y)=ax+by+c,
\]

moving one sample right gives

\[
f(x+1,y)=f(x,y)+a,
\]

and moving one sample up gives

\[
f(x,y+1)=f(x,y)+b.
\]

So once `f` is known at one location, neighboring values can be obtained with additions.

This is the mathematical foundation of the lecture's repeated optimization pattern:

```text
expensive direct evaluation
↓
precompute coordinate derivatives/increments
↓
cheap neighboring updates
```

# Task 25 — Integrated exam-style question

Explain how the course progresses from the naïve line equation to modern parallel triangle rasterization. Your answer should connect all of these terms in a causal order:

- `y = mx + B`
- DDA
- midpoint decision variable
- implicit functions
- spatial coherence
- shared-edge rule
- scanline triangle filling
- attribute interpolation
- edge functions
- tiles
- GPU parallelism

## Lecture connection

Lecture 6 as a whole.

## Solution

The naïve line algorithm evaluates

\[
y=mx+B
\]

repeatedly and rounds the result. It works conceptually but performs unnecessary repeated arithmetic.

**DDA** exploits **spatial coherence**: when x changes by one, y changes by a fixed slope, so the new y is obtained incrementally.

The **midpoint algorithm** goes further. Instead of computing the ideal y-value, it uses an **implicit function** whose sign at a midpoint tells which of two candidate samples is better. Because the implicit function is linear, its **decision variable** can also be updated incrementally using fixed additions.

When rasterizing triangle meshes, exact boundary cases require a **shared-edge ownership rule** so adjacent triangles neither leave cracks nor double-own samples.

For filled triangles, **scanline rasterization** walks coherent left/right edges and fills the interval between them. Fragment **attributes are interpolated**, and these values can again be updated incrementally because nearby samples are coherent.

However, scanline processing contains sequential dependencies. Modern GPUs need massive independent work.

An **edge function** classifies an arbitrary sample relative to one triangle edge. Three edge-function sign tests determine triangle coverage without requiring previous scanline state.

Therefore the screen can be divided into **tiles**, with many tiles and samples tested independently. This organization sacrifices some sequential reuse but enables far more **GPU parallelism**.

The conceptual evolution is:

```text
recompute everything
↓
reuse neighboring values
↓
turn geometry into sign tests
↓
make coverage independently evaluable
↓
parallelize over tiles/samples
```

# 27. Exam traps

## Trap 1 — fragment = pixel

Wrong. A fragment is a candidate contribution and may fail later tests.

## Trap 2 — projection = rasterization

Wrong. Projection maps geometry geometrically; rasterization decides discrete coverage.

## Trap 3 — DDA and midpoint are unrelated algorithms

They are stages of the same optimization story: exploit coherence and replace recomputation with incremental updates.

## Trap 4 — the midpoint decision variable is a distance

Not necessarily. Its **sign** is what matters for deciding which side of the ideal line the test point lies on.

## Trap 5 — shared edges can simply be included by everybody

That can cause double coverage. A deterministic ownership rule is needed.

## Trap 6 — triangle rasterization only decides coverage

It also needs to produce/interpolate values needed at fragments.

## Trap 7 — scanline is automatically better because it reuses more work

Modern hardware also values parallelism. Tile/edge-function approaches allow independent work at massive scale.

## Trap 8 — edge function zero always means inside

Zero means the sample lies on an edge. Inclusion then depends on the chosen boundary ownership convention.

# 29. Final mental model

Rasterization starts with a mismatch:

```text
mathematics gives us continuous geometry
but
the display gives us discrete sample locations
```

The naïve solution is to repeatedly evaluate geometric equations. The lecture then teaches you why that is wasteful.

Nearby samples are related. Lines, planes, edge functions and interpolated attributes are linear enough that moving one grid step changes their values predictably.

So the core strategy becomes:

```text
calculate once
↓
update incrementally
↓
make a cheap discrete decision
```

That produces DDA, midpoint decisions, edge walking and incremental interpolation.

But sequential reuse conflicts with massive GPU parallelism. Edge functions solve that second problem by allowing arbitrary samples to be classified independently. Tiles then organize those independent tests into parallel blocks of work.

The deepest takeaway is therefore:

> **Rasterization is the disciplined conversion of continuous primitives into discrete fragments. Its algorithms are built around two competing opportunities: exploit spatial coherence to reuse calculations, and expose independent coverage tests so enormous amounts of work can run in parallel.**
