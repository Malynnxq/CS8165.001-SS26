OpenGL vs. Vulkan
 How about Vulkan?
(cid:127) More modern than OpenGL
(cid:127) Designed for high performance and low-level GPU control
(cid:127) Better suited for complex, large-scale rendering engines

 Vulkan becomes important once we want more control and efficiency

3. Memory Layout Description
 Memory layout is described by the following function
 glVertexAttribPointer(attribIndex, size, type, normalized, stride, offset);
(cid:127) attribIndex – attribute number (0 for position, later more ...)
(cid:127) size – number of components per vertex (2 for xy, 3 for xyz)
(cid:127) type – base type (typically GL_FLOAT or GL_DOUBLE)
(cid:127) normalized – normalize integer values w hen converting to floating-point numbers
to [-1,1] (signed) or [0,1] (unsigned)
(cid:127) stride – gap between data in memory (0: data directly adjacent to each other)
(cid:127) offset – is added to the start address specified with glBufferData
(can often be simply set to 0)
 First, attributes must be activated
 glEnableVertexAttribArray(attribIndex);
 The coordinates of the vertices are assigned to the attribute index 0,
but there is also the possibility to assign further attributes
(e.g., colors, normals, ...)

Chapter Summary
 Rendering pipeline consist of geometry stage and rasterization stage
 Geometric primitives (mostly triangles) are transformed through different
coordinate systems in the geometry stage
 Rasterization results in fragments, which are pixel predecessors
 Fragments have to endure a sequence of tests in the rasterization stage, in
order to be promoted to pixels
