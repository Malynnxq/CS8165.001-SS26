Visibility Determination
 Problem
(cid:127) Given scene objects and virtual camera
(cid:127) Determine visible parts of scene objects
(cid:127) Not occluded by same scene object
(cid:127) Not occluded by other scene objects
(cid:127) Not pointing away from camera for closed, opaque objects
 Two equivalent perspectives on the problem
(cid:127) Determination of visible lines and surfaces
(Visible Surface Determination, VSD)
(cid:127) Hidden Surface Removal (HSR) and Hidden Line Removal (HLR)
 Quality criteria for visibility determination algorithms
(cid:127) Generality: algorithms should be applicable for all types of geometry
(e.g., convex/non-convex, polygons, polyhedra)
(cid:127) Performance: determining hidden scene object parts
has to be more cost effective than their rasterization costs
(cid:127) Robustness: algorithms should be robust to numerical errors

Robert‘s Algorithm
 First algorithm for object-based visible line determination
(cid:127) Input: set of convex 3D scene objects
(cid:127) Output: set of visible lines
 Procedure: perform for all scene objects the following steps
1. Remove self-occluded surfaces through back-face culling
2. Compute shadow volume based on silhouette edges
3. Clip edges against all computed shadow volumes
4. Connect remaining edges per scene object

BSP Tree Construction
 Choose a hyperplane from scene geometry for root node
and associate that plane with root node, split remaining geometry at plane
 Proceed recursively with the two resulting sets of scene geometries
and check each polygon against hyperplane
(cid:127) Coinciding: associate with node
(cid:127) Intersecting: subdivide into two parts and sort into half-spaces
 Termination criterion for recursion
(cid:127) Stop if a node has fewer than a specified number of polygons
(cid:127) Stop when every single polygon is assigned to a node

BSP Tree Construction – Pseudo Code
Function buildBSPTree(BSPNode node, List of Polygons list)
// Select one polygon to use as a hyperplane
Polygon p = Get first polygon from list
Set node.plane to the plane of polygon p
Add polygon p to node.geometry
// Initialize lists for front and back polygons
Declare frontList, backList as List of Polygons
// Distribute remaining polygons into the corresponding half-spaces
While there is another polygon p in list
Evaluate the spatial relation of polygon p with respect to node.plane
Switch (relation)
Case COINCIDENT:
Add p to node.geometry
Case INFRONT:
Add p to frontList
Case BACK:
Add p to backList
Case SPANNING:
Split polygon p by node.plane, distribute pieces to frontList and backList
// Recursively build the BSP tree in both half-spaces
Set both node.front and node.back to null
If frontList is not empty
Create a new BSPNode for node.front
Call buildBSPTree recursively for node.front with frontList
If backList is not empty
Create a new BSPNode for node.back
Call buildBSPTree recursively for node.back with backList

Visibility Determination – Pseudo Code
Function BSPHiddenSurfaceTraversal(BSPNode node, Point eye)
// Calculate the signed distance from the eye point to the partition plane
float distance = classifyPoint(node.plane, eye)
If distance < 0 Then
// Eye-point is on the back side of the plane
Call BSPHiddenSurfaceTraversal for node.front with eye
Draw the geometry in node
Call BSPHiddenSurfaceTraversal for node.back with eye
Else If distance > 0 Then
// Eye-point is in front of the plane
Call BSPHiddenSurfaceTraversal for node.back with eye
Draw the geometry in node
Call BSPHiddenSurfaceTraversal for node.front with eye
Else
// Eye-point is exactly on the partition plane
Call BSPHiddenSurfaceTraversal for node.back with eye
Call BSPHiddenSurfaceTraversal for node.front with eye

Procedure warnockHSR(Polygons list, Viewport vp)
If isSimple(list, vp) Then
// Base case: Simple enough scenario to draw directly
drawPolygons(list)
Else
// Recursive case: The viewport is too complex and needs to be subdivided
Declare vp1, vp2, vp3, vp4 as Viewport
// Subdivide the current viewport into four equal parts
subdivideViewPort(vp, vp1, vp2, vp3, vp4)
// Build lists of polygons that are relevant for each subdivided viewport
List<Polygon> list1 = selectPolygonsInViewport(list, vp1)
List<Polygon> list2 = selectPolygonsInViewport(list, vp2)
List<Polygon> list3 = selectPolygonsInViewport(list, vp3)
List<Polygon> list4 = selectPolygonsInViewport(list, vp4)
// Recursively apply the Warnock algorithm to each subdivided viewport
warnockHSR(list1, vp1)
warnockHSR(list2, vp2)
warnockHSR(list3, vp3)
warnockHSR(list4, vp4)
End If
End Procedure

(cid:127) Depth buffers have in general between 16 and 32 bit accuracy

Depth Buffer Precision
 Depth buffer precision is limited by its bit-depth (e.g., 16-bit, 24-bit, 32-bit),
which determines how finely depth can be distinguished
 Depth buffer precision is not linear: denser at near- and sparser at far-
clipping plane ⇒ depth conflicts can occur especially at greater distances

Z-Fighting 2/2
 Mitigation through depth buffer properties
(cid:127) Use higher precision buffers by switching from 24-bit to 32-bit depth
(cid:127) Adjust near and far planes: bringing near plane out- and far plane inwards
reduces the depth range, improving effective depth buffer precision
 Mitigating through rendering properties
(cid:127) Polygon offset: slightly offset surfaces that might otherwise z-fight,
commonly used for rendering shadows or decals
(cid:127) Staggered rendering: render scenes in multiple passes with adjusted
depth ranges to ensure that precision is focused where it is most needed

 Ray march in 𝜀 steps and check all scene objects for intersection
Function intersect(const Ray& ray, const List of SceneObjects& sceneObjects) const
Initialize t as 0.0 // Starting point for ray parameter
Initialize epsilon as 0.01 // Small increment for ray parameter
// Loop to incrementally trace the ray through the scene
Loop for a large number of iterations (up to BIG_NUMBER)
Calculate rayPos as ray.origin + ray.direction * t // Current position along the ray
// Check for intersections with all scene objects
For each sceneObject in sceneObjects
If sceneObject intersects with rayPos
Set result.position to ray.origin + ray.direction * t // Intersection position
Set result.color to sceneObject.color // Color at the intersection
Set result.normal to sceneObject.normal // Normal at the intersection
Return result // Return the intersection details
Increment t by epsilon // Move further along the ray
Return result // Return the result with default values if no intersection is found
