Umbra and Penumbra
▪ Point light sources
• Result in hard shadows
• High intensity contrast between shadowed andnon-shadowed region
▪ Area light sources
• Result in soft shadows
• Core shadow (umbra): area completely occluded wrt. light source
• Penumbra (Penumbra): area only partially occludedwrt. light source
▪ Size of shadow region depends on
• Area of light source
• Distance of light source to scene object

Observations 1/2
▪ Possible shadow generation approaches
• Shadows as surfaces: exploit hidden-surface algorithms
• Shadows as projection: create shadows from A to Bby projecting A onto B from light source
▪ Static vs. dynamic scenes
• Shadows are static in scenes with static lighting and scene objects (shadow computation
possible as preprocess)
• Shadows are dynamic in scenes with dynamic lighting and/ordynamic scene objects(shadows
must be computed per frame)

Static Shadow Polygons
▪ Render dark polygons to represent shadow regions
• Cast ray from light source through center of shadow-casting objects
• Position dark polygon where ray intersects shadow-receiving object
▪ Disadvantages
• Static shapes cannot represent geometry of dynamic scene objects
• Single intersection of ray and shadow-receiver can’t capture soft shadows
• Incorrect parts of the shadow may be drawn

Stencil Shadow Volume
▪ Generation of shadow volumes per frame
• Works well for scenes with few moving objects
• Expensive for complex shadow volumes
• Improvement by simplifying shadow-casting geometries
▪ Four rendering passes required
• Render scene exclusively with ambient lighting
• Render front-face shadow polygons and increment stencil buffer
• Render back-face shadow polygons and decrement stencil buffer
• Render parts of scene that are not in shadow (stencil buffer equals 0)
▪ However, some details have to be considered!

Implementation
▪ Determine visible scene objects
• Render scene without writing in color buffer
▪ Represent shadow volume in stencil buffer
• Initialize stencil buffer with 0
• Render front-face shadow polygons and increment stencil buffer by 1
• Render back-face shadow polygons and decrement stencil buffer by 1
• => Shadowed image regions are marked by >0 in stencil buffer
▪ Render shadowed parts of shadow-receiving scene objects
• Render only where stencil value >0
▪ Render non-shadowed parts of shadow-receiving scene objects
• Render only where stencil value =0

Shadow Volume Conclusions
▪ Advantages
• Shadow-casting and shadow-receiving objects can have arbitrary shapes
• Applicable for multiple light sources
• Level-of-detail adaptable through approximated geometries
• Shadow volumes for static pairs of objects and lights can be precalculated
• Self-shadowing possible
▪ Disadvantages
• Many new polygons need to be rendered
• Long thin triangles are very expensive in rasterization
• Bit depth of the stencil buffer may not be sufficient for very complex scenes (buffer overflow)
• Scene objects must be closed (no holes)
