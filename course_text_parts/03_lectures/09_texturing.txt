Why Textures Matter
▪ Geometry defines shape
▪ Textures define appearance detail
▪ This separates visual complexity from geometric complexity
▪ Instead of modeling every scratch, brick, pore, label, or color variation, we store it in texture data
▪ Textures are efficient
• Fewer triangles
• Richer visual detail
• Reusable material assets
• Fast GPU sampling and filtering

Texels, Channels, and Meaning
▪ Texel: smallest sample element of a texture
▪ In 2D, a texel is analogous to a pixel
▪ Texels store numeric channel values
▪ Common channel layouts
• R, RG, RGB, RGBA
• Depth
• Integer labels or IDs
▪ Channel layout does not define semantic meaning
• RGB can store color or an encoded normal vector
• R can store roughness, metallic, height, mask, or density
• Meaning is defined by shader and material model

Color Textures vs. Data Textures
▪ Some textures store perceptual color
▪ Other textures store numeric shader data
▪ Color textures
• Base color / albedo
• Emissive color
• Usually decoded as sRGB
▪ Data textures
• Normal, roughness, metallic
• Ambient occlusion, height, masks
• Must be treated as linear data
▪ Rule: use sRGB decoding only for color textures
▪ Wrong color-space handling causes incorrect shading

Magnification vs. Minification
▪ Magnification
• Map few texels onto many pixels
• Two filtering approaches
• Nearest: Take the nearest texel
• Bilinear interpolation: Interpolation between 4 nearest texels
▪ Minification
• Map many texels to one pixel
• Aliasing: high-frequency signal reconstructionfrom low frequency
sampling
• Main filtering approach
• Average over all associated texels
• Computationally expensive

MIP Mapping (multum in parvo = ‘much in little’)
▪ Efficient scheme for sampling texture values
▪ Representation of a texture at different resolution levels(levels of Detail, LoDs)
▪ Exploiting a texture pyramid (here: 2D, analog for 1D and 3D)
• Each pyramid level contains filtered textureof half resolution of previous level
• Each layer contains only quarter of texelsof previous layer
• Individual layers are precalculated

▪ Texture wrapping specifies border handling behavior when accessing texture outside the
[0, 1]D

▪ Texture wrapping mode is part of texture specification, and specified separately for each texture
dimension
▪ Two main modes exist
• Clamping: GL_CLAMP_TO_EDGE, GL_CLAMP_TO_BORDER
• Repetition: GL_REPEAT, GL_MIRRORED_REPEAT

Texture Wrapping 2/4
▪ GL_CLAMP_TO_EDGE
• Texture coordinates below 0 become 0
• Texture coordinates above 1 become 1
• Results in constant continuation of texture
▪ GL_CLAMP_TO_BORDER
• Texture coordinates below 0 become 0
• Texture coordinates above 1 become 1
• Coordinates originally outside range mapped to definable border color

Texture Wrapping 3/4
▪ GL_REPEAT
• Texture coordinates ignore digits before decimal point, and use digits after decimal point as
texture coordinates
• Results in periodic continuation of normalized texture space
▪ GL_MIRRORED_REPEAT
• Texture coordinates ignore digits before decimal point, and digits after decimal point are
subtracted from 1 in alternating manner before used as texture coordinates
• Results in periodic, mirrored continuation of normalized texture space

▪ Environment mapping simulates reflections by sampling an image of the surrounding scene
▪ The environment is treated as if it were infinitely far away

Environment Mapping Types 2/2
▪ Spherical environment maps
• compact representation in one 2D texture
• strong distortion near the border
• difficult filtering and interpolation behavior
▪ Dual-paraboloid maps

• introduce distortion and seam issues
• rarely used in modern teaching pipelines

• direct hardware support
• natural representation for skyboxes, reflections, and IBL
▪ In modern real-time rendering, cube maps are the standard representation!

Spherical Environment Mapping
▪ A sphere map stores the environment as seen in a perfectly reflective sphere
▪ It was useful before cube maps became widely supported in graphics hardware
▪ It is mainly relevant today as historical context
▪ Important limitations
• non-uniform distortion
• singularity at the outer border

Sphere Map Distortion
▪ Sphere-map texels represent differently sized regions of the environment
▪ Distortion is especially problematic in the outer region of the map
▪ Hardware performs linear texture filtering, not spherical interpolation
▪ For modern real-time graphics, this is one reason cube maps are preferred

Practical Cube-Map Issues
▪ Cube-map reflections are an approximation
• environment is assumed to be far away
• object does not reflect itself
• other moving objects are usually missing
▪ Important implementation details
• use mipmaps for glossy / blurred reflections
• enable seamless cube-map filtering where available
• sample color maps in the correct color space
• use dynamic cube maps only when reflections must update

Cube Mapping Pros and Cons
▪ Advantages
• direct hardware support
• limited distortion
• no pole singularities
• natural representation for directional data
• suitable for skyboxes, reflections, and IBL
▪ Disadvantages
• seams may occur at cube-face boundaries
• face orientation must be consistent
• filtering and compression can reveal edges
• local reflections are only approximate

Spherical Environment Mapping Assumptions
▪ Environment assumed far from object to be textured
▪ Self-reflection not taken into account
• Object to be textured assumed a convex shape(even if it is not geometrically convex)
▪ No other moving objects in the environment
• Interreflection is not taken into account
▪ Object to be textured curved as much as possible
• Visually suppresses distortions

Spherical Environment Mapping Conclusions
▪ Advantages
• Contains panoramic image of an environment in a single texture
• Filtering and LoD formation takes place within a single texture
▪ Disadvantages
• Singularity along the outer disc border
• Linear interpolation performed by graphics hardware
• Distortion and filtering problems increase in front half-space
• 2D texture memory is not fully utilized
• Generation of panoramic images not supported by graphics hardware

Ray Marching Volume Rendering
▪ Instead of drawing slices, cast one ray per fragment through the volume
▪ Repeatedly sample the 3D texture along the ray
▪ Apply the transfer function at every sample
▪ Composite samples until the ray exits the volume or becomes opaque

Quality and Performance Trade-Offs
▪ Step size
• smaller steps improve quality but increase cost
• larger steps are faster but can miss thin structures
▪ Opacity correction
• keeps appearance stable when step size changes
▪ Acceleration
• early ray termination
• empty-space skipping
• bricking and paging for large volumes
• lower-resolution mip levels for previews
▪ Main trade-off: image quality versus samples per ray

3D Texturing Takeaways
▪ 3D textures generalize 2D texture lookup from surfaces to volumes
▪ They are useful for solid materials, volumetric effects, and sampled scientific data
▪ Trilinear interpolation provides smooth access to voxel grids
▪ Volume rendering turns sampled data into color and opacity along viewing rays
▪ Transfer functions and compositing determine what becomes visible
▪ Performance is dominated by memory footprint and number of samples
